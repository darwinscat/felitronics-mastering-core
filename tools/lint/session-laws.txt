# THE SCOPE OF THE SESSION-LAWS LINT (tools/lint/check-session-laws.mjs) — which files it holds to which rule, and the
# only exceptions it grants. The RULES live in the script (what counts as mutable state, which headers and calls are
# refused and why); what they are applied to lives here, so that widening the scope or granting an exception is a line
# a reviewer reads rather than an edit inside a lexer.
#
# Format (one per line; the reason is required):
#   scan          <path>  <rules>         <why>   a file, or a directory walked whole (any directory named tests/
#                                                  excepted); <rules> is a comma-separated subset of globals,os,zone
#   allow-global  <file>  <name>          <why>   one named mutable global in a file the globals rule scans. Each must
#                                                  match exactly one declaration, or the list has rotted and is red.

# --- the brain: every law of docs/SESSION.md that a lexer can hold, on every file of the module
scan  modules/session            globals,os,zone  the mastering session; its tests are not the session and are excepted

# --- the C surface over it
scan  tools/fc_session_abi.h     globals,os       the header a shell compiles: declarations and a C integer header, nothing else
scan  tools/wasm/fc_session.cpp  globals          the C boundary; a handle must name a session between calls, so it keeps a table
allow-global  tools/wasm/fc_session.cpp  g_slots      the handle table: what a handle names between two calls
allow-global  tools/wasm/fc_session.cpp  g_callState  the poison flag: it must outlive the call that never returned
